# dsh-duet 工作方式

设置中的「工作方式」与交互、播报两个语音按钮分别控制不同功能：

| 工作方式 | 任务处理 |
| --- | --- |
| 输入模式 | 帮你把需求输入文本框（传统模式） |
| 代理模式 | 直接帮你执行任务（推荐） |

Super Agent 是同一安装中的 Host 模块，依赖 `dsh-duet-superagent/duet`。
主插件继续管理语音、形象和设置；任务模块复用原生 Engine、Runtime 和任务持久化。
任务引擎源码位于 `vendor/dsh-duet-superagent/`，与插件一起按固定提交检出。

发布前先在子模块运行 `pnpm install --frozen-lockfile` 和 `pnpm run check`，再在插件根目录运行
`npm ci`。Super Agent 的编译产物与运行依赖通过 `bundleDependencies` 随插件分发，用户只需安装
`dsh-duet`。`npm pack` 会核验模块与已构建源码一致；解包后再运行
`node scripts/verify-agent-package.mjs --package-root <解包目录>`，再运行
`node scripts/test-installed-package.mjs <安装包.tgz>`，验证独立目录安装同一份包。

工作方式在连接创建时确定，切换后重新开启语音；已提交任务继续运行。
安装或升级后，尚未选择工作方式时会先看到「想怎么用 dsh-duet？」。代理模式标为推荐，但不预选。
可以稍后再选；当前标签页刷新不重复提示，下次主动开启语音时再选。选好后仍可在设置中切换。输入模式可以操作已有的
Ungrouped 会话；创建会话和代理模式仍需要选择工作区。
代理任务绑定设置中选定的工作区，不跟随其他页面的焦点变化。
每个工作区复用一个 `dsh-duet 主 Session`，重连不会重复创建；主会话不参与普通任务编号。
任务模型默认跟随 DSH 默认模型；高级设置中的任务管理模型默认与任务模型相同。
设置不修改 DSH 的全局默认模型；已启动的任务保留原模型，管理模型在当前轮次结束后切换。

直接点击模式卡片即可切换。代理卡片会标明「同意完整权限并启用」；还没选过工作区时，选好工作区后才启用。
`danger-full-access` 可以执行命令、读写文件和访问网络，
通常不逐项请求确认；工作区是起始目录，不是文件访问的隔离边界。
该权限只应用于 duet 管理的会话。切回输入模式即关闭代理授权，已提交任务保留运行，
需要停止时在对应 DSH 会话中停止。
首次选择需要按「确定」才会生效。可以使用 dsh-duet 专属工作区，也可以选择自己的工作区。
新模式使用 `duet_agent_v1`，收到消息与执行结果分别处理。
概貌使用短标识、独立排序和增量字段更新；重连可以恢复任务与待答问题。

语音请求传递用户原话，由任务助手结合上下文判断要新建、继续还是停止哪个任务。
回答待答问题时可以携带 `reply_to`；请求不接受双工模型指定的 `task_id`。
任务通知仍保留任务与执行轮次标识，用于区分并行任务和结果归属。
送达回执只表示收到请求，不代表任务完成；未确认送达时不自动重复提交。
